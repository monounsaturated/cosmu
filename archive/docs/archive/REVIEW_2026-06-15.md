## 3. Faster iteration — the architecture (the operator's "we're too slow")

**Root cause:** every backtest runs **serially on one core**. `data/backtest.py:run_strategy_backtest` is
the atomic unit; FarmLoop, finder, matrix_search, scheduler all wrap it in a Python `for` loop. There is
**zero** `ProcessPool`/`.map`/`concurrent.*` on the money path. The documented Modal fan-out
(`docs/RESEARCH_THROUGHPUT.md` T1) was **never built**. The gate's FDR brake is the *intended* throughput
governor (more drafts ≠ more winners) — keep it; the *unintended* governor is single-core serialism.

**The build (highest leverage first):**

1. **Modal `.map` fan-out** — `run_matrix_cell` (`research/matrix_search.py:86`) is already self-contained
   and map-ready. Add a `matrix_cell` Modal function + a `sweep` local-entrypoint that `.starmap`s over
   `(asset, timeframe)` cells → ~50 parallel containers instead of a 50-cell serial loop. Wire `pnpm
   modal:sweep`. **Point it at the alt-joined feature space** (the unsearched ~75 features), not the
   exhausted bar-TA grid — that's where the next *novel* survivor (if any) lives. (Diff in local prompt.)
2. **One-command batch** — `cosmu/lab/batch.py`: `--n 50 --theme T --gate` authors N (now that
   `_MAX_BATCH=64`), writes inbox, runs ONE cohort via `scan_inbox`. Composes existing functions.
3. **Theme diversity** — theme batches collapse to near-dupes the novelty gate then hard-rejects
   (`lab/author.py:88-94`, only 4 templates; `strategize.py:155` only 8 angles). Widen angles/templates so
   "50 from a theme" yields ~50 *distinct* specs, not ~6.
4. **Bar-cache hoist** — FarmLoop re-reads + re-parses the bar JSON per candidate
   (`evolution/loop.py:579-582`). Load `{symbol: bars}` once per cohort (mirror `finder.py:266-271`).
5. **`/research/automate` skill** (shipped this session: `.claude/skills/research-to-cohort/`) — chains
   deep-research → generate N → batch backtest → gate → report, orchestrated with the Agent tool. This is
   the "Claude deep search automated with a CC sub-agent" ask. Works with today's serial sweep; gets 50×
   faster once (1) lands.

**Parallel CODE agents (not compute):** the repo rule is **one branch/worktree per agent, never two in one
tree** (proven branch-stomping, `docs/LESSONS.md`). Use the Agent tool's `isolation: "worktree"` +
`run_in_background: true` (this review used 9 parallel read-only agents). For *backtests*, prefer Modal
`.map` (container parallelism, no worktree collision risk) over agent fan-out.
