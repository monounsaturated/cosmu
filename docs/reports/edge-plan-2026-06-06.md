PIT lag), BUT if LunarCrush **revises historical values post-hoc**, our one snapshot captured future-informed
values → look-ahead contamination → any social edge is FAKE. **Run `profile-source` on the LunarCrush panel
(revision-safety + PIT-lag audit) FIRST.** If history is revised, exclude pre-first-ingest rows and rely on
**forward-collected** data + the Simulation (forward-test) stage to confirm. This is why social edges must clear
forward-test, not just backtest.
